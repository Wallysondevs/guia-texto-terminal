null, //, ? e try

Dados reais têm buracos. Esta aula mostra como o jq trata campos nulos e erros sem quebrar o script.

Você vai aprender
  • Achar e tratar null com //.
  • if/then/else.
  • ?, try/catch e -e.

Todas as saídas desta aula foram colhidas de verdade num Linux (Debian 13, com GNU Bash 5.2, GNU sed 4.9, GNU awk 5.2 e jq 1.7) em português (pt_BR.UTF-8), dentro da pasta de teste ~/guia-texto-teste com os arquivos de exemplo. Antes de cada caixa a pasta foi recriada do zero, então um comando que altera arquivo numa caixa não afeta a seguinte.

A ideia: dados reais têm buracos

Em JSON de verdade, campos faltam, vêm null ou com tipo inesperado. A Carla, no usuarios.json, tem "email": null. Esta aula mostra como o jq lida com isso: o valor padrão //, o ? que cala erros, o if, o try e o código de saída com -e.

1. Onde está o null

$ jq '.[].email' usuarios.json
"ana@exemplo.com"
"bruno@exemplo.com"
null
"diego@exemplo.com"
$ jq '.[] | select(.email == null) | .nome' usuarios.json
"Carla Dias"
$

2. Valor padrão: //

a // b devolve a, a não ser que ele seja null ou false; aí devolve b:

$ jq -r '.[] | .email // "(sem e-mail)"' usuarios.json
ana@exemplo.com
bruno@exemplo.com
(sem e-mail)
diego@exemplo.com
$ jq '.peso // 0' produto.json
0
$
.email
o valor normal.
//
“ou, se for null/false”.
"(sem e-mail)"
o valor padrão.

3. if / then / else

$ jq -r '.[] | if .ativo then "\(.nome): ativo" else "\(.nome): inativo" end' usuarios.json
Ana Souza: ativo
Bruno Lima: inativo
Carla Dias: ativo
Diego Rocha: ativo
$ jq -r '.[] | "\(.nome): \(if (.tags | length) == 0 then "sem tags" else (.tags | join(",")) end)"' usuarios.json
Ana Souza: admin,vendas
Bruno Lima: vendas
Carla Dias: sem tags
Diego Rocha: suporte
$

4. Calar erros: ? e try

Um filtro com ? no fim engole o erro e simplesmente não produz resultado. O try … catch permite trocar o erro por outra coisa:

$ jq '.[] | .email | ascii_downcase' usuarios.json
jq: error (at usuarios.json:6): explode input must be a string
"ana@exemplo.com"
"bruno@exemplo.com"
$ jq '.[] | (.email | ascii_downcase)?' usuarios.json
"ana@exemplo.com"
"bruno@exemplo.com"
"diego@exemplo.com"
$ jq -r '.[] | try (.email | ascii_downcase) catch "falhou"' usuarios.json
ana@exemplo.com
bruno@exemplo.com
falhou
diego@exemplo.com
$

No primeiro comando, o jq parou no erro da Carla e o Diego nem apareceu. A mensagem “explode input must be a string” quer dizer que o ascii_downcase recebeu algo que não é texto (o null); ela veio antes das outras linhas porque a saída de erro não espera na fila. Com ?, a Carla foi pulada; com try/catch, virou “falhou”.

5. -e: o código de saída

Com -e, o jq sai com código 1 se o último resultado for null ou false. Ótimo para if em scripts do Bash:

$ jq -e '.preco' produto.json; echo "código: $?"
12.5
código: 0
$ jq -e '.peso' produto.json; echo "código: $?"
null
código: 1
$

Quando dá errado

Arquivo que não existe

O jq avisa e sai com código 2:

$ jq . nada.json; echo "código: $?"
jq: error: Could not open file nada.json: Arquivo ou diretório inexistente
código: 2
$
Abrir null

Abrir com [] um campo que não existe é erro (“Cannot iterate over null”: não dá para percorrer null). O []? resolve:

$ jq '.cores[]' pedidos.json
jq: error (at pedidos.json:10): Cannot iterate over null (null)
$ jq '.cores[]?' pedidos.json; echo "código: $?"
código: 0
$

Resumo

  • // dá um valor quando o campo é null.
