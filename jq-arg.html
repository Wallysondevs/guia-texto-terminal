Variáveis de fora (--arg, --argjson)

Em scripts, o valor do filtro vem de uma variável do shell. O jq tem opções próprias para isso, sem brigar com aspas.

Você vai aprender
  • --arg para textos e --argjson para números.
  • -n e -s.
  • $ENV e o padrão curl … | jq.

Todas as saídas desta aula foram colhidas de verdade num Linux (Debian 13, com GNU Bash 5.2, GNU sed 4.9, GNU awk 5.2 e jq 1.7) em português (pt_BR.UTF-8), dentro da pasta de teste ~/guia-texto-teste com os arquivos de exemplo. Antes de cada caixa a pasta foi recriada do zero, então um comando que altera arquivo numa caixa não afeta a seguinte.

A ideia: valores de fora para dentro do filtro

Em scripts, o valor do filtro (a cidade, o status, a idade mínima) costuma vir de uma variável do shell. Colar a variável dentro das aspas do jq dá dor de cabeça com aspas e é inseguro. O jq tem opções próprias: --arg passa um texto, --argjson passa um valor JSON (número, true, lista…). Dentro do filtro, eles viram $nome.

1. --arg: um texto

$ jq -r --arg cidade 'São Paulo' '.[] | select(.cidade == $cidade) | .nome' usuarios.json
Ana Souza
Diego Rocha
$ status=pago; jq -c --arg s "$status" '[.pedidos[] | select(.status == $s) | .id]' pedidos.json
[1042,1044]
$
--arg cidade 'São Paulo'
cria $cidade com o texto São Paulo.
select(.cidade == $cidade)
usa a variável no filtro.

2. --argjson: um número

O --arg sempre cria texto. Comparar idade (número) com texto não dá o que você espera: no jq, todo número é “menor” que qualquer texto, e o filtro não devolveu ninguém. Com --argjson, o 30 é número de verdade:

$ jq -r --arg min 30 '.[] | select(.idade > $min) | .nome' usuarios.json
$ jq -r --argjson min 30 '.[] | select(.idade > $min) | .nome' usuarios.json
Bruno Lima
Diego Rocha
$

3. -n e -s

-n (null input) roda o filtro sem ler entrada nenhuma: bom para criar JSON do zero. -s (slurp, “engolir”) junta todas as entradas numa lista só:

$ jq -n --arg nome Ana --argjson idade 28 '{nome: $nome, idade: $idade}'
{
  "nome": "Ana",
  "idade": 28
}
$ jq -c '.nome' produto.json usuarios.json 2>&1 | head -2
jq: error (at usuarios.json:6): Cannot index array with string "nome"
"caderno"
$ jq -s 'length' produto.json pedidos.json
2
$

No segundo comando, o jq aplicou .nome em cada arquivo: no produto.json deu “caderno” e no usuarios.json (uma lista) deu erro. A mensagem de erro apareceu primeiro porque a saída de erro não espera na fila. No terceiro, com -s, os dois arquivos viraram uma lista de 2 itens.

4. Variáveis de ambiente: $ENV

Variáveis de ambiente também estão disponíveis, em $ENV (ou env):

$ LOJA_CIDADE=Recife jq -n -r '$ENV.LOJA_CIDADE'
Recife
$
O padrão com APIs

Na vida real: curl -s https://api.exemplo.com/pedidos | jq -r --arg s pago '.pedidos[] | select(.status == $s) | .id'. O guia não acessa a internet; o cat pedidos.json | faz o papel do curl.

$ cat pedidos.json | jq -r --arg s pago '.pedidos[] | select(.status == $s) | .id'
1042
1044
$

Quando dá errado

Variável não criada

Usar $cidade sem o --arg é erro de compilação (“$cidade is not defined”: $cidade não foi definida):

$ jq '.[] | select(.cidade == $cidade)' usuarios.json
jq: error: $cidade is not defined at <top-level>, line 1:
.[] | select(.cidade == $cidade)                        
jq: 1 compile error
$
--argjson com texto

O valor do --argjson tem de ser JSON válido. Um texto sem aspas não é:

$ jq -n --argjson nome Ana '$nome'
jq: invalid JSON text passed to --argjson
Use jq --help for help with command-line options,
or see the jq manpage, or online docs  at https://jqlang.github.io/jq
$

Resumo

  • Nunca cole variáveis do shell dentro do filtro: use --arg.
  • Números e booleanos vão com --argjson.
  • -s engole tudo numa lista.
