O que é o jq (. e -c)

O jq entende JSON, o formato das APIs. Esta aula mostra o filtro mais simples, o ., que já deixa qualquer JSON legível.

Você vai aprender
  • Objetos, listas e valores do JSON.
  • O filtro . e a opção -c.
  • Ler do pipe e entender os erros de JSON inválido.

Todas as saídas desta aula foram colhidas de verdade num Linux (Debian 13, com GNU Bash 5.2, GNU sed 4.9, GNU awk 5.2 e jq 1.7) em português (pt_BR.UTF-8), dentro da pasta de teste ~/guia-texto-teste com os arquivos de exemplo. Antes de cada caixa a pasta foi recriada do zero, então um comando que altera arquivo numa caixa não afeta a seguinte.

A ideia: JSON é texto com estrutura

JSON é o formato das APIs e de muitos arquivos de configuração: objetos entre chaves ({"nome": "caderno"}), listas (arrays) entre colchetes (["azul", "verde"]), textos entre aspas, números, true, false e null. O sed e o awk enxergam JSON como linhas soltas; o jq entende a estrutura e navega por ela.

1. O filtro .: mostrar bonito

O programa mais simples do jq é . (“a entrada inteira”). Ele lê o JSON e devolve formatado, com recuo:

$ cat produto.json
{"nome": "caderno", "preco": 12.5, "estoque": {"loja": 40, "deposito": 120}, "cores": ["azul", "verde", "preto"]}
$ jq . produto.json
{
  "nome": "caderno",
  "preco": 12.5,
  "estoque": {
    "loja": 40,
    "deposito": 120
  },
  "cores": [
    "azul",
    "verde",
    "preto"
  ]
}
$

Na sua tela, o jq ainda pinta as chaves, os textos e os números com cores diferentes. A coleta foi gravada sem terminal, por isso as caixas do guia não têm cor.

2. -c: tudo numa linha

O contrário: -c (compact) devolve cada resultado numa linha só, ótimo para passar adiante num pipe:

$ jq -c . usuarios.json | cut -c 1-70
[{"id":1,"nome":"Ana Souza","email":"ana@exemplo.com","idade":28,"cida
$

3. Do pipe

Como as outras ferramentas, o jq lê do |. Na vida real, a entrada costuma vir de uma API, com curl -s https://… | jq .. Neste guia, tudo é local: os arquivos fazem o papel da resposta da API.

$ echo '{"loja": "Papelaria", "aberta": true}' | jq .
{
  "loja": "Papelaria",
  "aberta": true
}
$ cat pedidos.json | jq -c '.loja'
"Papelaria da Ana"
$
Mensagens do jq em inglês

O jq não tem tradução: mesmo num Linux em português, as mensagens de erro saem em inglês. Elas aparecem aqui exatamente como o jq escreveu, com a explicação em português.

Quando dá errado

JSON quebrado

O quebrado.json termina no meio, sem fechar a chave. O jq diz onde a leitura parou (“Unfinished JSON term at EOF”: termo JSON inacabado no fim do arquivo):

$ jq . quebrado.json
jq: parse error: Unfinished JSON term at EOF at line 2, column 0
$
Esqueceu o filtro

Com arquivo, o jq precisa do filtro antes do nome. Sem ele, o jq acha que produto.json é o programa e lê produto como o nome de uma função sem argumentos (produto/0) que não existe (“is not defined”: não está definida):

$ jq produto.json
jq: error: produto/0 is not defined at <top-level>, line 1:
produto.json
jq: 1 compile error
$
