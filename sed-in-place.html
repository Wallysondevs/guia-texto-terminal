Editando o arquivo (-i e backup)

A opção -i grava a mudança no próprio arquivo. Útil e perigosa: esta aula mostra como usar com segurança, sempre na pasta de teste.

Você vai aprender
  • Gravar no arquivo com -i.
  • Guardar o original com -i.bak.
  • As armadilhas: -n com -i e o -in.

Todas as saídas desta aula foram colhidas de verdade num Linux (Debian 13, com GNU Bash 5.2, GNU sed 4.9, GNU awk 5.2 e jq 1.7) em português (pt_BR.UTF-8), dentro da pasta de teste ~/guia-texto-teste com os arquivos de exemplo. Antes de cada caixa a pasta foi recriada do zero, então um comando que altera arquivo numa caixa não afeta a seguinte.

A ideia: gravar a mudança no próprio arquivo

Até aqui, o sed só mostrou o resultado na tela. A opção -i (in-place, “no lugar”) grava a mudança no arquivo. É poderosa e perigosa: não tem “desfazer”. Por isso, a regra do guia é só usar -i na pasta de teste e, de preferência, com backup.

Confira antes de gravar

Rode o comando sem -i primeiro e olhe a saída. Só quando estiver certo, acrescente o -i. Se estragar, recrie os arquivos com bash criar-arquivos.sh.

1. -i: gravar

Repare que o sed -i não mostra nada na tela. O resultado está no arquivo:

$ sed -i 's/claro/escuro/' config.txt
$ grep tema config.txt
tema=escuro
$

2. -i.bak: gravar com backup

Com um sufixo colado no -i, o sed guarda uma cópia do original antes de gravar:

$ sed -i.bak 's/8080/9090/' config.txt
$ ls config.txt*
config.txt
config.txt.bak
$ grep porta config.txt config.txt.bak
config.txt:porta=9090
config.txt.bak:porta=8080
$
-i.bak
grava no arquivo e guarda o original como config.txt.bak.
s/8080/9090/
a mudança.
config.txt
o arquivo alterado.

Para desfazer, basta trazer o backup de volta: mv config.txt.bak config.txt.

3. Vários arquivos de uma vez

O -i vale para todos os arquivos da linha, cada um gravado separadamente. Aqui, “Ana” virou “Aninha” nos dois de uma vez (e “ana paula”, minúsculo, ficou como estava):

$ sed -i 's/Ana/Aninha/' nomes.txt vendas.csv
$ grep -c Aninha nomes.txt vendas.csv
nomes.txt:1
vendas.csv:4
$

4. O cuidado com o -n

-n com -i grava só o que foi impresso. Esquecer o p deixa o arquivo vazio:

$ sed -n -i 's/ERRO/FALHA/' log.txt
$ wc -l log.txt
0 log.txt
$

Quando dá errado

-i sem arquivo

O -i precisa de um arquivo para gravar; não funciona com pipe:

$ echo teste | sed -i 's/t/T/'
sed: nenhum arquivo de entrada
$
-in não é -i -n

O que vem colado no -i é o sufixo do backup. -in não liga o -n: cria um backup com sufixo n:

$ sed -in 's/uva/UVA/' frutas.txt
$ ls frutas*
frutas.txt
frutas.txtn
$

Escreva -n -i separados, ou -ni.

Referência rápida

Você digitaO que faz
sed -i 's/a/b/' arqgrava a troca em arq.
sed -i.bak 's/a/b/' arqgrava e guarda arq.bak.
mv arq.bak arqdesfaz, trazendo o backup de volta.
sed -n -i '/x/p' arqdeixa no arquivo só as linhas com x.

Missões

Rode na sua pasta ~/guia-texto-teste (com os arquivos de exemplo originais) e cole o que o terminal respondeu. O botão Conferir compara com o que a saída real precisa ter.

Missão: troque sim por nao no debug de config.txt com -i e depois mostre a linha com grep debug config.txt.



sed -i 's/debug=sim/debug=nao/' config.txt
grep debug config.txt

debug=nao

Missão: com -i.bak, troque uva por kiwi em frutas.txt e liste os arquivos frutas*.



sed -i.bak 's/uva/kiwi/' frutas.txt
ls frutas*

frutas.txt
frutas.txt.bak

Resumo

  • Teste sem -i, confira, e só então grave.
  • -i.bak guarda o original.
  • -n -i sem p esvazia o arquivo.
