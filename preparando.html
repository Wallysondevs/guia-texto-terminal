A pasta de teste e os arquivos de exemplo

Antes de editar e filtrar, você precisa de algo para editar. Esta aula cria a pasta de treino e apresenta os arquivos inventados que aparecem em todas as aulas.

Você vai aprender
  • Criar a pasta ~/guia-texto-teste com o script criar-arquivos.sh.
  • O que tem em cada arquivo de exemplo.
  • Como voltar os arquivos ao original.

Todas as saídas desta aula foram colhidas de verdade num Linux (Debian 13, com GNU Bash 5.2, GNU sed 4.9, GNU awk 5.2 e jq 1.7) em português (pt_BR.UTF-8), dentro da pasta de teste ~/guia-texto-teste com os arquivos de exemplo. Antes de cada caixa a pasta foi recriada do zero, então um comando que altera arquivo numa caixa não afeta a seguinte.

A ideia: uma caixa de areia

O sed e o awk conseguem alterar arquivos. Para treinar sem medo, todo o guia trabalha numa pasta só para isso, a ~/guia-texto-teste, com arquivos inventados: nomes fictícios, vendas de uma papelaria, um log de sistema, JSON de usuários e pedidos. Se algo der errado, você apaga a pasta e cria de novo.

1. Criar a pasta e os arquivos

Os arquivos de exemplo estão neste site, na pasta arquivos/ (por exemplo, vendas.csv e usuarios.json). O jeito mais rápido é o script criar-arquivos.sh, que cria todos de uma vez, sem internet. Baixe-o (ou copie o conteúdo dele num arquivo com esse nome) e rode estes comandos:

mkdir -p ~/guia-texto-teste
cd ~/guia-texto-teste
bash ~/Downloads/criar-arquivos.sh

Na coleta, o script foi rodado numa pasta vazia chamada nova, dentro da pasta de teste. Ele avisou onde criou os arquivos, e o ls mostrou o que apareceu:

$ mkdir nova && cd nova && bash ../criar-arquivos.sh && ls

Voltar ao original

Rodou um sed -i e estragou um arquivo? Rode bash criar-arquivos.sh de novo dentro da pasta: ele reescreve todos os arquivos de exemplo como eram.

Quando dá errado

Fora da pasta de teste

Se você esquecer o cd ~/guia-texto-teste, os comandos não acham os arquivos. Na coleta, entramos de propósito numa pasta vazia:

$ mkdir vazia && cd vazia && cat nomes.txt
cat: nomes.txt: Arquivo ou diretório inexistente
$

“Arquivo ou diretório inexistente” quase sempre quer dizer: pasta errada ou nome digitado errado. Confira com pwd e ls.
