Procurando linhas (grep)

Antes de editar com o sed, quase sempre a gente procura. O grep mostra só as linhas que contêm um texto.

Você vai aprender
  • Buscar um texto num arquivo.
  • As opções -i, -v, -c, -n, -w e -o.
  • Buscar em vários arquivos e ler o código de saída.

Todas as saídas desta aula foram colhidas de verdade num Linux (Debian 13, com GNU Bash 5.2, GNU sed 4.9, GNU awk 5.2 e jq 1.7) em português (pt_BR.UTF-8), dentro da pasta de teste ~/guia-texto-teste com os arquivos de exemplo. Antes de cada caixa a pasta foi recriada do zero, então um comando que altera arquivo numa caixa não afeta a seguinte.

A ideia: achar as linhas que interessam

O grep mostra só as linhas que contêm um texto. Ele é o primo mais simples do sed e do awk: os dois também filtram linhas, mas o grep é o mais rápido de digitar quando só se quer ver.

1. Buscar um texto

$ grep ERRO log.txt
2026-03-02 08:17:45 ERRO  falha no pagamento pedido=1042
2026-03-02 09:12:03 ERRO  tempo esgotado no servidor de e-mail
2026-03-02 10:45:20 ERRO  falha no pagamento pedido=1047
$
grep
o comando de busca.
ERRO
o padrão procurado.
log.txt
onde procurar.

2. As opções do dia a dia

-i ignora maiúsculas e minúsculas; -v inverte (mostra as que não têm); -c conta; -n mostra o número da linha:

$ grep -i rato texto.txt
O rato roeu a roupa do rei de Roma.
O rato fugiu para o mato.
Rato que é rato não volta.
$ grep -v INFO log.txt
2026-03-02 08:17:45 ERRO  falha no pagamento pedido=1042
2026-03-02 09:01:37 AVISO estoque baixo produto=caderno
2026-03-02 09:12:03 ERRO  tempo esgotado no servidor de e-mail
2026-03-02 10:45:20 ERRO  falha no pagamento pedido=1047
2026-03-02 11:02:15 AVISO disco 85% cheio
$ grep -c ERRO log.txt
3
$ grep -n AVISO log.txt
4:2026-03-02 09:01:37 AVISO estoque baixo produto=caderno
9:2026-03-02 11:02:15 AVISO disco 85% cheio
$

-w exige a palavra inteira, e -o mostra só o pedaço que casou. “ato” aparece dentro de “rato” e “mato” em 3 linhas, mas como palavra sozinha não aparece em nenhuma:

$ grep -c ato texto.txt
3
$ grep -cw ato texto.txt
0
$ grep -o 'pedido=[0-9]*' log.txt
pedido=1042
pedido=1043
pedido=1047
$

3. Vários arquivos

Com mais de um arquivo, o grep põe o nome na frente. O -l lista só os nomes dos arquivos que têm o padrão:

$ grep Ana nomes.txt vendas.csv | head -4
nomes.txt:Ana
vendas.csv:2026-03-02,Ana,caderno,3,12.50
vendas.csv:2026-03-03,Ana,caneta,5,2.00
vendas.csv:2026-03-04,Ana,mochila,2,89.90
$ grep -l caderno *
criar-arquivos.sh
log.txt
pedidos.json
produto.json
quebrado.json
vendas.csv
$

Quando dá errado

Arquivo que não existe

O grep avisa, mas continua nos outros arquivos:

$ grep ERRO log.txt nada.txt
log.txt:2026-03-02 08:17:45 ERRO  falha no pagamento pedido=1042
log.txt:2026-03-02 09:12:03 ERRO  tempo esgotado no servidor de e-mail
log.txt:2026-03-02 10:45:20 ERRO  falha no pagamento pedido=1047
grep: nada.txt: Arquivo ou diretório inexistente
$
Nada encontrado não é erro na tela

Quando não acha nada, o grep não escreve nada. Quem conta a história é o código de saída: 0 achou, 1 não achou, 2 erro.

$ grep FATAL log.txt; echo $?
1
$ grep ERRO log.txt > /dev/null; echo $?
0
$
