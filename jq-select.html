O | do jq e select

Dentro do jq também existe pipe, e o select filtra itens por condição. Juntos, são o grep do JSON.

Você vai aprender
  • O | dentro do programa jq.
  • select com comparações, and, or, not.
  • Regex com test e listas com any.

Todas as saídas desta aula foram colhidas de verdade num Linux (Debian 13, com GNU Bash 5.2, GNU sed 4.9, GNU awk 5.2 e jq 1.7) em português (pt_BR.UTF-8), dentro da pasta de teste ~/guia-texto-teste com os arquivos de exemplo. Antes de cada caixa a pasta foi recriada do zero, então um comando que altera arquivo numa caixa não afeta a seguinte.

A ideia: o pipe de dentro e o filtro

Dentro do programa jq também existe |: a saída de um filtro vira a entrada do próximo, igual ao pipe do Bash. E o select(condição) deixa passar só os itens em que a condição é verdadeira, o grep do JSON.

1. O | do jq

.[] | .nome é o mesmo que .[].nome: abra a lista e, de cada item, pegue o nome. Com o pipe fica mais fácil de ler quando o caminho cresce:

$ jq '.[] | .nome' usuarios.json
"Ana Souza"
"Bruno Lima"
"Carla Dias"
"Diego Rocha"
$ jq '.pedidos[] | .itens[] | .produto' pedidos.json | sort -u
"caderno"
"caneta"
"estojo"
"mochila"
$

2. select: filtrar

Só os usuários ativos; só os maiores de 30; só os de São Paulo:

$ jq '.[] | select(.ativo) | .nome' usuarios.json
"Ana Souza"
"Carla Dias"
"Diego Rocha"
$ jq '.[] | select(.idade > 30) | .nome' usuarios.json
"Bruno Lima"
"Diego Rocha"
$ jq '.[] | select(.cidade == "São Paulo") | .nome' usuarios.json
"Ana Souza"
"Diego Rocha"
$
.[]
cada usuário.
select(.idade > 30)
deixa passar só quem tem idade maior que 30.
.nome
dos que passaram, o nome.

3. and, or, not

$ jq '.[] | select(.ativo and .idade < 30) | .nome' usuarios.json
"Ana Souza"
"Carla Dias"
$ jq '.pedidos[] | select(.status == "pago" or .status == "pendente") | .id' pedidos.json
1042
1043
1044
$ jq '.[] | select(.ativo | not) | .nome' usuarios.json
"Bruno Lima"
$

4. Regex: test

test("regex") é verdadeiro se o texto casa. Com "i" no segundo argumento, sem diferenciar maiúsculas:

$ jq '.[] | select(.nome | test("^[AB]")) | .nome' usuarios.json
"Ana Souza"
"Bruno Lima"
$ jq '.[] | select(.cidade | test("paulo"; "i")) | .id' usuarios.json
1
4
$

5. Filtrar dentro de listas

Os pedidos que têm pelo menos um item de caneta, usando any:

$ jq '.pedidos[] | select(any(.itens[]; .produto == "caneta")) | .cliente' pedidos.json
"Bruno"
"Diego"
$

Quando dá errado

select sem parênteses

A condição do select vai entre parênteses. Sem eles, o jq procura uma função select sem argumentos (select/0), que não existe:

$ jq '.[] | select .ativo' usuarios.json
jq: error: select/0 is not defined at <top-level>, line 1:
.[] | select .ativo      
jq: 1 compile error
$
Um = só

Em jq, comparar é ==. Um = só é atribuição: o resultado dela é um objeto, que conta como verdadeiro, então todos passaram no filtro (e a cidade nem mudou na saída, porque o select devolve o item original):

$ jq -c '.[] | select(.cidade = "Recife") | {nome, cidade}' usuarios.json
{"nome":"Ana Souza","cidade":"São Paulo"}
{"nome":"Bruno Lima","cidade":"Rio de Janeiro"}
{"nome":"Carla Dias","cidade":"Belo Horizonte"}
{"nome":"Diego Rocha","cidade":"São Paulo"}
$

Missão: mostre o nome dos usuários com idade menor que 30.



jq '.[] | select(.idade < 30) | .nome' usuarios.json

"Ana Souza"
"Carla Dias"

Resumo

  • | no jq passa o resultado adiante.
  • select deixa passar só o que é verdadeiro.
  • Compare com ==, nunca com =.
